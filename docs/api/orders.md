# Orders API

Base path: `/api/v1/orders`

Customer and product UUIDs are opaque references. The API does not look up customers or products, calculate prices or totals, or check inventory.

## Create an order

`POST /api/v1/orders`

### Request

```http
Content-Type: application/json
Idempotency-Key: optional-client-key
```

```json
{
  "customerId": "f46d8cdf-4b2d-4c76-83a8-183bf7953fd9",
  "items": [
    {
      "productId": "b69f6a4e-2b47-4612-87c4-146b47528f4c",
      "quantity": 2
    }
  ]
}
```

| Field | Constraints |
|---|---|
| `customerId` | Required UUID |
| `items` | Required array containing 1–100 entries |
| `items[].productId` | Required UUID |
| `items[].quantity` | Required positive 32-bit integer (`1`–`2147483647`) |
| `Idempotency-Key` | Optional; when supplied, must be 1–128 characters and not consist solely of whitespace |

Each item entry is retained separately and in request order, including repeated `productId` values.

### Success response

Returns `201 Created` with `Content-Type: application/json` and a `Location` header identifying the new resource:

```http
Location: /api/v1/orders/21bcd235-7050-43a8-9bf5-f95504b71ac0
```

```json
{
  "id": "21bcd235-7050-43a8-9bf5-f95504b71ac0",
  "customerId": "f46d8cdf-4b2d-4c76-83a8-183bf7953fd9",
  "items": [
    {
      "productId": "b69f6a4e-2b47-4612-87c4-146b47528f4c",
      "quantity": 2
    }
  ],
  "status": "CREATED",
  "createdAt": "2026-10-28T10:00:00Z"
}
```

`id` is generated by the server. `createdAt` is the server-generated UTC creation time in ISO 8601 format. `status` is initially `CREATED`. No price or total is returned.

### Idempotency

An idempotency key is scoped to the `customerId` and retained for the lifetime of the order. Repeating the same ordered item data with the same customer and key returns the original `201 Created` representation and `Location`; it does not create another order. Reusing the key for different ordered item data returns `409 Conflict`. Another customer may use the same key independently. Requests without a key create distinct orders.

## Retrieve an order

`GET /api/v1/orders/{id}`

`id` must be a UUID. An existing order returns `200 OK` with `Content-Type: application/json` and the same representation as the create response. A malformed UUID returns `400 Bad Request`; a valid UUID for an order that does not exist returns `404 Not Found`.

## Errors

Errors use `Content-Type: application/problem+json` and an RFC 9457 Problem Details object. The `status` member matches the HTTP status. Validation details do not echo submitted values, and unexpected failures do not expose internal details.

Example:

```json
{
  "type": "about:blank",
  "title": "Invalid request",
  "status": 400,
  "detail": "Request validation failed.",
  "instance": "/api/v1/orders"
}
```

| HTTP status | Meaning |
|---|---|
| `400 Bad Request` | Required fields are missing, UUIDs are malformed, item or quantity constraints fail, or a supplied idempotency key is blank or exceeds 128 characters |
| `404 Not Found` | The requested UUID does not identify an existing order |
| `409 Conflict` | The customer reused an idempotency key with different ordered item data |
| `500 Internal Server Error` | An unexpected failure occurred; the response contains only a generic detail |

Creating an order, its item entries, and any supplied idempotency key is one database transaction. If persistence fails, none of those records is committed.
